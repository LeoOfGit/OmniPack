OmniPack 用户指南 (User Guide)

欢迎使用 OmniPack！愿本程序成为您管理 Python 虚拟环境、Node.js 项目依赖以及 Windows 系统包管理器 WinGet 的得力工具。

1. 界面布局全解析

OmniPack 的主界面经过精心设计，分为四个核心交互区域。

1.1 顶层工具栏 (Global Toolbar)

这是执行全局搜索、过滤与批量指令的指挥中心。

  • 选择控制 (All/None)：快速全选或全取消当前主界面中所有可见的包。
  • 搜索框 (Search)：实时过滤各个环境卡片中显示的包名，支持模糊匹配。
  • 待更新过滤 (Only Show Outdated)：一键隐藏所有已是最新版本的包，让您可以集中处理需要升级的项目。系统会智能评估每个更新的安全性：约束冲突（橙色 ⚠）和构建变体切换（蓝色 🔀）的包不会被自动选中，但若是存在安全中间版本（蓝色 🔒）则会被自动选中。
  • 全局刷新 (Refresh All)：重新扫描所有配置环境的本地包列表，并查询云端最新版本。
  • 批量更新 (Batch Update)：对当前所有【已勾选】且【云端有新版本】的包发起并行升级指令（仅作用于包，不更新解释器/Node 运行时）。
  • 批量卸载 (Batch Remove)：对所有当前勾选的包发起卸载指令（会有二次确认弹窗）。
  • 设置 (Settings)：直接跳转至环境配置与系统设置页面。

1.2 环境主体卡片 (Env Canvas)

左侧区域，以卡片形式展示每一个 Python 虚拟环境或 Node.js 项目。

  • 环境信息：每张卡片顶部显示环境别名、路径、运行时版本；当检测到同周期补丁更新时，会显示 当前 -> 最新。
  • 操作按钮：
    • ↻：刷新当前环境
    • ⇧：仅更新当前环境内所有可更新的包
    • Py / Nd：更新环境运行时本体（Python/Node）
    • +：添加包
  • 包列表：列出当前环境下安装的所有包及其版本。

1.3 集成伪终端与控制台 (Integrated PTY Terminal & Live Console)

右侧区域是 OmniPack 的核心执行显示中心，在 V10 中经过全新架构重构，支持两种互补的显示与交互模式（双控制台设计）：

  • 交互式伪终端 (Real Terminal)：
    • 实时深度交互：这是一个真正的 PTY 终端 Shell（默认启用）。不仅可以实时流式呈现底层包管理命令的执行日志，还能接受您的全盘键盘输入。这意味着在遇到 git clone 账户密码输入、或安装中途需要输入 y/n 进行确认等高交互场景时，您可以直接在终端中打字并回车，彻底打破了以往“模拟控制台”容易产生进程死锁的硬伤。
    • ANSI 丰富染色：底层搭载了 pyte 色彩染色引擎，完美解析 ANSI 转义序列。这意味着 uv、pip、npm 在终端里绘制的动态高色彩字符进度条、或者带颜色的错误堆栈，均能在控制台内平滑流畅地流动展示，还原了极其丝滑的原生终端视觉体验。
    • 环境与目录静默同步 (Active Sync)：终端与左侧的环境状态实现了深度联动。每当您切换或激活左侧的环境卡片时，主程序会静默且无感地发送 cd 改变目录或调用激活 venv 的指令，实现“界面点到哪，终端跟到哪”的顺畅同步。
    • 操作容器化与 UI 快刷：在 PTY 终端模式下，面板按钮触发的“更新”、“安装”或“卸载”均会直接转化为 CLI 命令写进终端窗口中运行。命令末尾自动追加一个唯一的 UUID Marker（标记）。主程序后台捕捉该 Marker 以判定命令执行完毕，并立刻对环境进行增量快速刷新 (Fast Refresh)，大大减少了界面的重绘卡顿。
    • 键盘高级组合：完美拦截 Tab 键命令补全、上下方向键回溯历史、Ctrl+C 强行中断子任务，以及 Ctrl+V 系统剪贴板文字粘贴。
  • 只读模拟控制台 (Simulated Console)：
    • 如果您在设置中将模式切换为只读模拟控制台，它将作为安全保底存在，被动地以富文本日志形式展示命令的 stdout 与 stderr，且提供基于正则表达式的 ANSI 字符剔除过滤。
    • 右键支持“清空控制台”、“复制选区”以及“打开日志文件所在目录”等通用功能。

1.4 状态栏反馈 (Status Bar)

位于窗口最底部，提供实时的统计与全局功能入口。

  • 左侧统计区：Envs: {n} | Packages: {m} ( {u} Outdated )。实时反映当前扫描出的环境总数、包总数及待更新统计。
  • 中间状态区：显示当前正在执行的操作（如 "Ready", "Scanning...", "Installing..."）。
  • 右侧切换区：
    • Python / Node.js / WinGet 按钮：用于在不同的包管理面板之间快速切换（WinGet 面板仅在 Windows 系统下可见）。
    • 💡 Guide 按钮：点击即可弹出本用户指南窗口。
注意：若程序获得了管理员权限，(Admin) 标识会显示在窗口的最上方标题栏。

2. 环境管理

2.1 统一导入流程 (Unified Intake)

在 Settings -> Python/NPM Environments 中，您可以管理项目的生命周期。

  • Python 环境 (Pip/uv)：
    • Detect System：扫描 PATH、注册表及桌面/用户目录下的 Python 解释器。
    • Add Manually：支持指向具体的 python.exe 解释器，或直接拖入包含 .venv 或 venv 的项目根目录。
  • Node.js 环境 (NPM)：
    • Add Manually：支持指向 package.json 文件或其所在的任意父目录。OmniPack 会自动溯源至项目根节点并解析项目名。
  • Batch Paste (批量导入)：您可以用Everything等搜索工具直接复制得到包含多个路径的多行文本，然后粘贴到输入框中，内置的 env_detector 引擎会自动执行去重、有效性验证和智能命名。。

2.2 环境操作说明

  • 拖拽重排：在列表项上长按图标即可上下拖动，调整环境在主界面的首选顺序。
  • 编辑环境：双击任意项可修改显示别名或修正因移动文件夹导致的路径变化。

3. Python (uv/pip) 深度管理

3.1 极速 uv 引擎

OmniPack 原生集成了一流的 uv 引擎。

  • 性能优势：对于复杂的依赖解析和大规模包安装，由于 uv 采用 Rust 编写且具备高效缓存，其速度通常是 pip 的数十倍。
  • 引擎更新：在 Settings -> Backend 设置中，可以一键触发 Check for Update 异步检查并在线更新 uv 引擎，无需重装程序。

3.6 实时文件系统联动 (Real-time Sync) (v12 新增)

OmniPack 内置了目录监听引擎 (File System Watcher)，无需任何配置即可生效。

  • 脱机操作同步：如果您在系统外部终端（如 cmd.exe）或 OmniPack 的内置 PTY 终端中直接运行了 pip install xxx 或 uv pip install xxx（NPM 面板则监听 node_modules），当命令结束后（无论成功或失败），OmniPack 会在静默 2 秒后自动抓取 site-packages / node_modules 目录的物理变化，并触发对应环境卡片的自动刷新。
  • 多端协作无缝衔接：该机制省去了频繁点击 ↻ 刷新按钮的繁琐步骤，实现了 UI 状态与硬盘物理状态的绝对实时一致。

3.2 依赖查询与依赖树

  • 层级展开：点击包名前的箭头，可无限向下展示该包引入的子依赖（Dependency Tree）。
  • 顶层视图：默认仅显示您主动安装的包，隐藏由于级联关系引入的被动安装包，极大减少视觉噪音。

3.3 本地缓存驱动的包搜索

  • 秒开响应：OmniPack 内置了超过 50 万笔热门 PyPI 包的数据缓存。在主界面或“添加包”对话框搜索时，其响应速度堪比本地文件搜索。
  • 搜索增强：搜索时支持对结果按版本范围进行筛选。

3.4 Python 运行时补丁更新（解释器本体）

  • 显示逻辑：Python 虚拟环境卡片优先读取 pyvenv.cfg 的版本元数据，避免系统 Python 小版本升级后导致显示偏差。
  • 更新检测：按同一 major.minor 周期检测最新补丁（例如 3.14.3 -> 3.14.4）。
  • 更新入口：当检测到可更新时，卡片显示 Py 按钮。点击后执行的是解释器/venv 升级流程，而非 pip 包升级。
  • 语义隔离：Py 与 ⇧ 独立，前者更新运行时，后者更新包。

3.5 风险感知更新 (Risk-Aware Updates)

当您开启工具栏的 "Outdated" 过滤时，并非所有可更新的包都会被自动选中。系统会对以下两类高风险更新进行智能拦截：

约束冲突（橙色 ⚠ 标识）

如果一个包的依赖者对其设定了版本上限（如 sympy 依赖 mpmath<1.4），而最新版超过了该上限，那么该包：

  • 不会被 Outdated 自动勾选
  • 版本文本显示为橙黄色：1.3.0 ➜ 1.4.1 ⚠
  • 鼠标悬停时提示："Latest version may break version constraints from: sympy"
  • 点击 ⇧ 按钮时弹出确认对话框，告知具体的约束来源

v12 智能安全升级（蓝色 🔒 标识） (Safe Intermediate Update)

v12 引入了更优雅的版本选择机制。若最新版被约束阻断，系统会自动扫描历史版本，寻找约束范围内允许的最高可用版本：

  • 版本文本显示为亮蓝色：1.3.0 ➜ 1.3.5 🔒 (latest 1.4.1)
  • 鼠标悬停时不仅显示冲突约束，还会特别提示 "Can safely update to 1.3.5"
  • 升级按钮变为蓝色且不需要二次确认，点击即可丝滑更新到 1.3.5
  • 此类型的受限包会被 Outdated 自动勾选，便于您批量升级

构建变体切换（蓝色 🔀 标识）

对于带有本地版本标识的包（如 torchaudio 2.11.0.dev20260506+cu132），当最新版不带该标识或标识不同时：

  • 不会被 Outdated 自动勾选
  • 版本文本显示为亮蓝色：2.11.0.dev+cu132 ➜ 2.11.0 🔀
  • 鼠标悬停时提示："Build variant may change: +cu132 → (none)"
  • 点击 ⇧ 按钮时弹出确认对话框，告知构建类型可能改变
手动操作不受限：以上拦截仅针对 Outdated 过滤的自动选中行为。您仍可手动勾选这些包，或直接点击其 ⇧ 按钮并确认风险后进行更新。

4. Node.js (npm) 项目管理

4.1 项目深度溯源

当您向 OmniPack 提供一个含有 Node.js 模块的任意深层文件夹时，它能自动确定真正的项目根目录，并精准展示出本地安装的模块版本。

4.2 在线搜索npm包

  • 在线搜索：从npm源搜索包，支持模糊匹配。

4.3 Dist-Tags 精准分发

OmniPack 将 NPM 的 Dist-Tags 机制进行了 GUI 封装。

  • 标签切换：在添加或更新包时，界面会整齐排列出所有远程 Release 通道（如 latest, beta, next, lts）。
  • 一键更新：点击对应标签卡片，系统会自动构造出如 npm install lodash@beta 这样的精准命令并执行。

4.4 Node.js 运行时补丁更新

  • 版本展示：Node 环境卡片会显示当前 Node 版本；若检测到同周期补丁更新，会展示 当前 -> 最新。
  • 更新入口：当可更新时显示 Nd 按钮，执行 Node 运行时升级。
  • 注意区分：Nd 更新 Node 运行时，⇧ 更新 npm 包，二者互不替代。

5. WinGet 系统包管理 (Windows 特有)

在 Windows 10/11 操作系统下，OmniPack 会自动在状态栏右侧注册 WinGet 包管理面板。它能对您系统上通过 Microsoft Store、WinGet 源或本地安装的桌面应用程序进行统一纳管。

5.1 双 Scope 环境自动探测 (Dual Scope Environment)

在主界面左侧会展示两个虚拟的系统环境：

  • System (Machine)：显示系统全局安装的软件（对应 winget://machine），通常位于 Program Files 目录下，更新时需要管理员权限。
  • User：显示当前用户专属安装的软件（对应 winget://user），通常位于用户个人目录下（如 %USERPROFILE%\AppData）。
  • 去重与范围智能判定 (Package Redistribution)：
    • OmniPack 内置了注册表物理路径审计机制。在扫描软件时，它会读取卸载路径，如果发现某个全局上报的软件其实物理安装在用户目录中，会自动将其归类到 User 虚拟环境中，保证信息的绝对精准。
    • 若同一个软件在系统和用户下都被安装了，卡片上会自动挂载 [Also Installed In User/Machine] 彩色徽章。

5.2 精准管理与锁定更新 (Full Actions & Pinning)

  • 获取更新 (Upgrades)：如果有可用更新，应用卡片上会显示 ⇧ 按钮。
  • 配置与锁定 (Blocking Pin)：
    • 点击应用卡片上的 ⚙ 配置按钮，会弹出专属配置框。
    • 支持设置 锁定更新 (winget blocking pin)。勾选“忽略此应用的更新（winget 锁定 Pin）”后，该应用在卡片上会挂载 [Pinned] 徽章，同时不会被工具栏 "Outdated" 选项自动勾选，避免大面积静默升级破坏特定软件版本。
    • 在配置框中，您还可以直接查看该软件的物理安装路径 (Uninstall Location) 并进行一键鼠标选定与复制，极其方便定位软件根目录。
  • 版本异常警告 (⚠ Newer Badge)：
    • 如果您从官网安装了比 WinGet 云端注册表更新的版本，系统会挂载 [⚠ Newer] 徽章警告，并阻止 Outdated 自动勾选它，防止误退级。
  • 安装新包 (Install)：
    • 点击卡片标题栏的 + 按钮，可以输入任意 WinGet 软件 ID（如 Google.Chrome）直接进行下载并静默或交互安装。
  • 智能范围回退机制 (Scope Fallback)：
    • 在 Machine 范围升级或安装大型软件如果遇到文件占用或写入权限问题而报错，OmniPack 会自动执行 Fallback，改为以 --scope user 尝试向用户范围下载安装，极大地提高了对软件版本自动更新的宽容度。

6. 设置中心 (Settings Center)

设置对话框是 OmniPack 的后台核心，按功能划分为六个清晰的选项卡（在 Windows 下）：

  1. Python/NPM Environments：环境列表维护区，支持增删改查及排序。
  2. Sources (注册表/镜像源)：
    • Follow System：尊重系统原有的配置。
    • Official：使用官方源。
    • Custom Preset：内置清华、阿里、华为等顶级镜像，一键切换。
    • 独立性：此处的设置仅针对 OmniPack 调用的命令生效，不会修改您的系统全局配置。
  1. Backend (核心引擎与缓存)：
    • uv 路径管理：手动指定或自动发现 uv 解释器。
    • PyPI Cache 同步：提供可视化的同步日志流。支持在程序运行期间静默同步几千万条记录，并可以随时随时暂停或取消。
  1. Proxy (代理配置)：
    • 协议分离：支持独立的 HTTP 和 HTTPS 代理设置。后台命令多数情况会使用https，建议两个都填。
    • 颗粒度控制：可单独勾选哪些域名（PyPI / NPM / GitHub）需要通过代理服务器。
    • 连通性测试：一键执行 Direct vs Proxy 响应延迟对比。
  1. WinGet (Windows 专属设置)：
    • 安装模式选择：支持配置 winget 安装和升级的全局行为模式：静默模式 (silent)、交互模式 (interactive)、默认模式 (default)。
    • winget.exe 路径：支持自动探测系统 PATH 上的 winget 进程，也支持手动浏览定位自定义的 winget 绝对路径。
    • 实时诊断状态：在设置页面内建 Diagnostics 控制台，可实时探知 winget 引擎是否可用、系统物理绝对路径、运行版本以及已启用的注册表源数量与可能上报的源配置错误。
  2. Terminal (终端与控制台配置)：
    • 控制台模式 (Console Mode)：支持用户在线自由切换控制台模式。可选 Simulated Console（经典的只读日志流模式，安全保底）与 Real Terminal（PTY 交互终端模式，默认启用）。
    • 默认 Shell 选择：支持配置内置伪终端默认调起的 Shell 程序（内置 cmd.exe、powershell.exe、pwsh.exe，并支持自定义特定外部 Shell 绝对路径）。

8. 常见问题解答 (FAQ)

Q: 某些npm应用已经发布新版本，但程序未能检测到
A: 很多npm的镜像源对nightly、preview等非正式版本的更新不及时，换用官方源即可。

Q: 为什么“状态栏”中的统计数量和卡片中看到的不一致？
A: 状态栏统计的是背景线程中所有已识别环境的总和，而卡片中显示的可能是经过“搜索框”过滤后的结果。

Q: 如何让我的 Python 环境显示在 Settings 列表最前面？
A: 在 Settings 对话框中，点击环境项左侧的拖拽手柄，将其移动到第一行并保存即可。

Q: “控制台”显示更新失败，但包版本却变了？
A: 这可能是由于底层工具（如 npm）在某些网络环境下报告了非零返回码。您可以点击对应卡片的“刷新”按钮查看环境的真实最新状态。

Q: 为什么我看不到 Py / Nd 运行时更新按钮？
A: 仅当检测到“同周期补丁可更新”时才显示该按钮。若当前已是最新补丁，或网络/源不可用导致暂时无法确认最新版本，按钮会隐藏。

Q: ⇧ 和 Py / Nd 有什么区别？
A: ⇧ 只更新环境内的包（pip/npm dependencies）；Py / Nd 更新的是解释器或 Node 运行时本体。

Q: (Admin) 状态是什么触发的？
A: 在 Windows 上以源码运行时，OmniPack 默认会自动请求管理员提权（可通过 OMNIPACK_REQUIRE_ADMIN=0 环境变量关闭）。提权成功后标题栏会显示 (Admin) 标记。打包发布版本则根据实际运行环境自动判断。

Q: 为什么在 macOS 或 Linux 上我看不到 WinGet 选项卡或面板？
A: WinGet 是 Windows 系统的内置包管理器，因此 OmniPack 仅在 Windows 操作系统下动态注册并显示 WinGet 面板和设置选项。

Q: WinGet 更新时提示需要管理员权限怎么办？
A: 升级系统全局应用（Machine 范围）通常需要写入 C:\Program Files 等系统敏感路径，这需要管理员特权。建议右键以管理员身份运行 OmniPack，或在系统提示时接受 UAC 提权请求。如果更新失败，OmniPack 会自动执行 Fallback，尝试以 --scope user 权限进行安装，最大程度保障部署成功。

Q: 为什么集成终端里常常输出一些带有 __OMNIPACK_OP_DONE_<uuid>__ 的字符串？
A: 这是 OmniPack 早期版本（v10/v11）为了实现“界面操作与真实终端完美联动”而设计的高性能标记（Marker）系统。在最新的 v12 版本中，底层已经升级为更稳健的临时文件标记机制（在系统临时目录生成 .done 文件以捕获退出码），从而彻底避免了正则拦截输出在某些复杂终端环境下的偶发抖动。如果您在终端中看到残留的 UUID 字符串，通常是早前复制粘贴的旧命令尚未清理，属正常现象，您可以安全地忽略或 cls / clear 清理。

Q: 在集成终端中，除了执行包管理器的命令，我还可以执行其他普通命令吗？
A: 完全可以！因为它是一个完整、真实的系统 Shell 伪终端（PTY）。您可以把它当成普通的 Terminal 使用，比如键入 git status、ls、dir 或者是运行您的 Python 脚本，它都完美支持，并且同样具有高色彩 ANSI 渲染和 Tab 自动补全功能。

Q: 我在设置中修改了终端默认 Shell，为什么没有立即变化？
A: 终端的 Shell 调起以及模式的切换（模拟/真实终端）由于涉及到底层 PTY 进程与线程的销毁与重新实例化，因此需要您重新启动 OmniPack 才会正式生效。

1. Full Interface Layout Analysis

OmniPack's main interface is meticulously designed and divided into four core interaction areas.

1.1 Global Toolbar

This is the command center for performing global searches, filtering, and batch operations.

  • Selection Control (All/None): Quickly select all or deselect all currently visible packages in the main interface.
  • Search Box (Search): Filter package names displayed in each environment card in real time, supporting fuzzy matching.
  • Filter Outdated (Only Show Outdated): Hide all up-to-date packages with one click, allowing you to focus on projects that need upgrading. The system intelligently evaluates the safety of each update: packages with constraint conflicts (orange ⚠) and build variant switches (blue 🔀) will not be automatically selected, but safe intermediate versions (blue 🔒) will be automatically selected.
  • Refresh All (Refresh All): Rescan the local package lists of all configured environments and query the latest versions in the cloud.
  • Batch Update (Batch Update): Initiate parallel upgrade commands for all currently [checked] packages that have [new versions in the cloud] (only affects packages, does not update the interpreter/Node runtime).
  • Batch Remove (Batch Remove): Initiate uninstall commands for all currently checked packages (a confirmation dialog will appear).
  • Settings (Settings): Jump directly to the environment configuration and system settings page.

1.2 Environment Cards (Env Canvas)

The left area displays each Python virtual environment or Node.js project in the form of a card.

  • Environment Info: The top of each card displays the environment alias, path, and runtime version; when a patch update within the same cycle is detected, it shows current -> latest.
  • Action Buttons:
    • ↻: Refresh the current environment
    • ⇧: Only update all upgradeable packages in the current environment
    • Py / Nd: Update the environment runtime itself (Python/Node)
    • +: Add packages
  • Package List: List all packages installed in the current environment and their versions.

1.3 Integrated PTY Terminal & Live Console

The right area is the core execution display center of OmniPack, reconstructed with a brand-new architecture in V10, supporting two complementary display and interaction modes (dual console design):

  • Interactive PTY Terminal (Real Terminal):
    • Real-time Deep Interaction: This is a genuine PTY terminal Shell (enabled by default). It not only streams the execution logs of underlying package management commands in real time but also accepts full keyboard input. This means in highly interactive scenarios, such as entering credentials during a git clone or typing y/n to confirm mid-installation, you can type directly in the terminal and press Enter. This completely resolves the process deadlocks common in previous "simulated consoles".
    • Rich ANSI Coloring: Equipped with the pyte color rendering engine at the bottom, it perfectly parses ANSI escape sequences. This means dynamic highly-colored text progress bars or colored error stacks drawn by uv, pip, and npm in the terminal flow smoothly in the console, restoring a silky-smooth native terminal visual experience.
    • Silent Environment & Directory Sync (Active Sync): The terminal is deeply linked with the environment status on the left. Whenever you switch or activate an environment card on the left, the main program silently and seamlessly sends a cd command to change directories or calls to activate venv, achieving a smooth synchronization of "wherever you click on the UI, the terminal follows."
    • Containerized Operations & UI Fast Refresh: In PTY terminal mode, "update", "install", or "remove" actions triggered by panel buttons are converted directly into CLI commands written and run in the terminal window. A unique UUID Marker (tag) is automatically appended to the end of the command. The main program captures this Marker in the background to determine command completion and instantly performs a Fast Refresh (incremental refresh) of the environment, significantly reducing UI redraw lagging.
    • Advanced Keyboard Shortcuts: Perfectly intercepts Tab key command completion, up/down arrow keys for command history, Ctrl+C to forcibly terminate subtasks, and Ctrl+V to paste text from the system clipboard.
  • Read-Only Simulated Console (Simulated Console):
    • If you switch the mode to a read-only simulated console in the settings, it serves as a safety backup, passively displaying the stdout and stderr of commands as rich text logs, and providing regex-based ANSI character stripping/filtering.
    • Right-click support for common functions like "Clear Console", "Copy Selection", and "Open Log File Directory".

1.4 Status Bar Feedback (Status Bar)

Located at the very bottom of the window, providing real-time statistics and global function entry points.

  • Left Stats Area: Envs: {n} | Packages: {m} ( {u} Outdated ). Reflects the total number of scanned environments, total packages, and outdated package stats in real time.
  • Middle Status Area: Displays the current operation being executed (e.g., "Ready", "Scanning...", "Installing...").
  • Right Switching Area:
    • Python / Node.js / WinGet Buttons: Used to quickly switch between different package management panels (the WinGet panel is visible only on Windows).
    • 💡 Guide Button: Click to pop up this user guide window.
Note: If the program obtains administrator privileges, the (Admin) badge will be displayed at the very top title bar of the window.

3. In-Depth Python (uv/pip) Management

3.1 Blazing-Fast uv Engine

OmniPack natively integrates the first-class uv engine.

  • Performance Advantage: For complex dependency resolution and large-scale package installations, uv is typically dozens of times faster than pip because it is written in Rust and has highly efficient caching.
  • Engine Update: In the Settings -> Backend settings, you can trigger a Check for Update with one click to asynchronously check and update the uv engine online, without reinstalling the program.

3.6 Real-time File System Sync (Real-time Sync) (New in v12)

OmniPack has a built-in File System Watcher that works out of the box without any configuration.

  • Offline Operation Sync: If you run pip install xxx or uv pip install xxx directly in an external system terminal (like cmd.exe) or in OmniPack's built-in PTY terminal (the NPM panel watches node_modules), OmniPack will automatically scan the physical changes in the site-packages / node_modules directory 2 seconds after the command ends (regardless of success or failure) and trigger an automatic refresh of the corresponding environment card.
  • Seamless Multi-Terminal Collaboration: This mechanism eliminates the tedious step of frequently clicking the ↻ refresh button, achieving absolute real-time consistency between the UI state and the physical disk state.

3.2 Dependency Querying & Dependency Tree

  • Hierarchical Expansion: Click the arrow in front of a package name to display the sub-dependencies introduced by this package infinitely downwards (Dependency Tree).
  • Top-level View: By default, only packages you actively installed are shown, while passively installed packages introduced by cascading relationships are hidden, greatly reducing visual noise.

3.3 Local Cache-Driven Package Search

  • Instant Response: OmniPack has a built-in data cache of over 500,000 popular PyPI packages. When searching on the main interface or the "Add Package" dialog, the response speed is comparable to local file search.
  • Search Enhancement: Supports filtering search results by version range.

3.4 Python Runtime Patch Updates (Interpreter Body)

  • Display Logic: Python virtual environment cards prioritize reading version metadata from pyvenv.cfg to avoid display discrepancies after upgrading minor versions of system Python.
  • Update Detection: Detects the latest patch within the same major.minor cycle (e.g., 3.14.3 -> 3.14.4).
  • Update Entry: When an update is detected, the card displays a Py button. Clicking it executes the interpreter/venv upgrade process, not a pip package upgrade.
  • Semantic Isolation: Py and ⇧ are independent; the former updates the runtime, and the latter updates the packages.

3.5 Risk-Aware Updates

When you turn on the "Outdated" filter in the toolbar, not all upgradeable packages will be automatically checked. The system will intelligently intercept the following two types of high-risk updates:

Constraint Conflict (Orange ⚠ Badge)

If a dependent of a package has set an upper version limit (e.g., sympy depends on mpmath<1.4), and the latest version exceeds this limit, then the package:

  • Will not be automatically checked by Outdated
  • Version text will display in orange-yellow: 1.3.0 ➜ 1.4.1 ⚠
  • Mouse hover tip: "Latest version may break version constraints from: sympy"
  • Clicking the ⇧ button will pop up a confirmation dialog informing you of the specific constraint source

v12 Intelligent Safe Upgrade (Blue 🔒 Badge) (Safe Intermediate Update)

v12 introduces a more elegant version selection mechanism. If the latest version is blocked by a constraint, the system automatically scans historical versions to find the highest available version allowed within the constraint range:

  • Version text will display in bright blue: 1.3.0 ➜ 1.3.5 🔒 (latest 1.4.1)
  • Mouse hover not only shows the conflicting constraint but also specifically tips "Safe to update to 1.3.5"
  • The upgrade button turns blue and does not require a secondary confirmation; click to update smoothly to 1.3.5
  • This type of restricted package will be automatically checked by Outdated, facilitating batch upgrades

Build Variant Switch (Blue 🔀 Badge)

For packages with a local version identifier (e.g., torchaudio 2.11.0.dev20260506+cu132), when the latest version does not have this identifier or has a different one:

  • Will not be automatically checked by Outdated
  • Version text will display in bright blue: 2.11.0.dev+cu132 ➜ 2.11.0 🔀
  • Mouse hover tip: "Build variant may change: +cu132 → (none)"
  • Clicking the ⇧ button will pop up a confirmation dialog informing you that the build type may change
Manual Actions Unrestricted: The interception above only targets the automatic checking behavior of the Outdated filter. You can still manually check these packages, or click their ⇧ buttons directly and confirm the risks to update.

5. WinGet System Package Management (Windows Specific)

Under Windows 10/11 operating systems, OmniPack automatically registers the WinGet package management panel on the right side of the status bar. It enables unified management of desktop applications installed on your system via the Microsoft Store, WinGet source, or local installers.

5.1 Dual Scope Environment Automatic Detection

Two virtual system environments will be displayed on the left side of the main interface:

  • System (Machine): Displays software installed system-wide (corresponding to winget://machine), usually located in the Program Files directory; updating requires administrator privileges.
  • User: Displays software installed exclusively for the current user (corresponding to winget://user), usually located in the user's personal directory (e.g., %USERPROFILE%\AppData).
  • Deduplication & Smart Scope Determination (Package Redistribution):
    • OmniPack has a built-in registry physical path audit mechanism. When scanning software, it reads the uninstallation path; if it detects that a system-wide reported software is actually physically installed in the user directory, it automatically categorizes it into the User virtual environment to ensure absolute accuracy of the information.
    • If the same software is installed in both system and user scopes, a colored [Also Installed In User/Machine] badge will automatically be mounted on the card.

5.2 Precise Management and Blocking Updates (Full Actions & Pinning)

  • Get Updates (Upgrades): If an update is available, the application card displays a ⇧ button.
  • Configuration & Pinning (Blocking Pin):
    • Clicking the ⚙ configuration button on an application card pops up its dedicated configuration box.
    • Supports setting a blocking pin (winget blocking pin). After checking "Ignore updates for this app (winget blocking pin)", the app will display a [Pinned] badge on the card and will not be automatically checked by the "Outdated" filter in the toolbar, preventing massive silent upgrades from breaking specific software versions.
    • In the configuration box, you can also directly view the software's physical installation path (Uninstall Location) and perform one-click selection and copying with the mouse, making it extremely convenient to locate the software's root directory.
  • Abnormal Version Warning (⚠ Newer Badge):
    • If you installed a version from the official website that is newer than the one registered in the WinGet cloud registry, the system will mount a [⚠ Newer] badge warning and prevent Outdated from automatically checking it, avoiding accidental downgrades.
  • Install New Package (Install):
    • Clicking the + button on the card title bar allows you to enter any WinGet software ID (e.g., Google.Chrome) to download and install it silently or interactively.
  • Intelligent Scope Fallback Mechanism (Scope Fallback):
    • If upgrading or installing a large software in the Machine scope fails due to file occupancy or write permission issues, OmniPack automatically performs a Fallback to attempt downloading and installing in the User scope with --scope user, significantly increasing tolerance for automatic software version updates.

8. Frequently Asked Questions (FAQ)

Q: Some npm packages have released new versions, but the program fails to detect them.
A: Many npm mirror registries are slow to update non-official releases like nightly or preview. Switching to the official registry will resolve this.

Q: Why is the statistical count in the "Status Bar" different from what I see in the cards?
A: The status bar calculates the sum of all identified environments in the background thread, whereas the cards display results that may have been filtered by the "Search Box".

Q: How do I make my Python environment display at the top of the Settings list?
A: In the Settings dialog, click the drag handle on the left side of the environment item, move it to the first row, and save.

Q: The "Console" shows update failed, but the package version actually changed?
A: This could happen because underlying tools (such as npm) report a non-zero exit code under certain network conditions. You can click the "Refresh" button on the corresponding card to check the true, latest status of the environment.

Q: Why can't I see the Py / Nd runtime update buttons?
A: These buttons are only displayed when a "patch update within the same cycle" is detected. If the current version is already the latest patch, or if the latest version cannot be temporarily confirmed due to network/source unavailability, the buttons will be hidden.

Q: What is the difference between ⇧ and Py / Nd?
A: ⇧ only updates packages inside the environment (pip/npm dependencies); Py / Nd updates the interpreter or Node runtime itself.

Q: What triggers the (Admin) status?
A: When running from source code on Windows, OmniPack automatically requests administrator elevation by default (which can be turned off via the OMNIPACK_REQUIRE_ADMIN=0 environment variable). After successful elevation, the (Admin) tag is displayed on the title bar. For packaged release builds, it is automatically determined based on the actual runtime environment.

Q: Why can't I see the WinGet tab or panel on macOS or Linux?
A: WinGet is a built-in package manager for Windows, so OmniPack dynamically registers and displays the WinGet panel and settings options only under the Windows operating system.

Q: What should I do if a WinGet update prompts for administrator privileges?
A: Upgrading system-wide applications (Machine scope) typically requires writing to sensitive paths like C:\Program Files, which demands administrator privileges. It is recommended to right-click and run OmniPack as administrator, or accept the UAC elevation prompt when requested by the system. If the update fails, OmniPack will automatically perform a Fallback to attempt installation with --scope user privileges to maximize deployment success.

Q: Why does the integrated terminal often output strings containing __OMNIPACK_OP_DONE_<uuid>__?
A: This is the high-performance Marker system designed in earlier versions of OmniPack (v10/v11) to achieve a "perfect link between UI operations and the actual terminal". In the latest v12, the underlying mechanism has been upgraded to a more robust temporary file tagging mechanism (generating .done files in the system temp directory to capture exit codes), thereby completely eliminating occasional jitter in regex interception of output under complex terminal environments. If you see leftover UUID strings in the terminal, it is usually because old command output from previous copy-pasting has not been cleared yet. This is normal, and you can safely ignore it or use cls / clear to clean it up.

Q: In the integrated terminal, can I execute other ordinary commands besides package manager commands?
A: Absolutely! Because it is a complete, genuine system Shell pseudo-terminal (PTY). You can use it as a regular Terminal, such as typing git status, ls, dir, or running your Python scripts; it is fully supported and also features rich-color ANSI rendering and Tab auto-completion.

Q: I modified the default terminal Shell in the settings, why didn't it change immediately?
A: Launching the terminal's Shell and switching modes (simulated/real terminal) involve the destruction and re-instantiation of underlying PTY processes and threads. Therefore, you need to restart OmniPack for the changes to take effect.
